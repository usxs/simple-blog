# 安全说明

## 设计原则

- **默认收紧**：后台接口全部要求登录；写操作要求同源；敏感文件 0600。
- **不依赖框架**：零第三方运行时依赖（除了处理图片的 `sharp`），减少供应链面。
- **失败可用**：目录不可写时接口返回 503 并提示，不让进程崩溃；通知失败只记日志。

## 已实现的保护

| 面 | 措施 |
| --- | --- |
| 口令存储 | scrypt（N=16384, r=8, p=1）+ 16 字节随机盐，恒定时间比较 |
| 登录限流 | 同 IP 15 分钟内失败 5 次 → 锁 15 分钟，并触发通知 |
| 会话 | 服务端只存 token 的 SHA-256；Cookie `HttpOnly` + `SameSite=Strict` + HTTPS 下 `Secure` |
| CSRF | 非 GET 请求校验 `Origin` / `Sec-Fetch-Site` |
| 枚举 | 登录失败统一提示「用户名或密码错误」；无凭据时也跑一次哈希 |
| 评论 | 算术验证码（10 分钟、一次性）+ 频率限制 + 审核制 |
| 上传 | 只接受 base64 JSON，大小受限；图片重新编码为 WebP |
| 黑名单 | 按 IP / 设备指纹封禁，命中直接 403 |
| 后台入口 | 可改名，旧地址返回 401 而非 302 |

## 你需要自己做的

1. **HTTPS**：Cookie 的 `Secure`、Passkey、剪贴板等能力都依赖它。
2. **不要暴露源站 IP**：用 Cloudflare 代理，源站防火墙只放行 Cloudflare 网段。
3. **强密码 + 两步验证**：后台「管理 → 账号安全」里开 TOTP 或 Passkey。
4. **定期备份**：文件即数据，误删/勒索都靠备份救。
5. **及时升级**：`docker compose pull && up -d`。

## 已知限制

- 单进程设计：限流计数、WebAuthn challenge 都在内存里，**不能多实例**水平扩展。
- 文件存储：并发写已用进程内写锁串行，但只在本实例内有效；多实例会互相覆盖。
- 邮件模板变量不做 HTML 转义之外的深度清洗，变量内容来自站点自身数据。
- 会话历史与黑名单保留在 `data/sessions.json`，长期不清理会缓慢增长（上限 80 条历史）。

## 规模上限参考

| 指标 | 建议 |
| --- | --- |
| 文章数 | 千篇以内（列表有解析缓存，搜索走内存索引） |
| 评论量 | 每天几百条以内 |
| 并发 | 单实例、几十个同时在线 |

超过上述规模，建议把评论/会话迁到 SQLite 或 Postgres。

## 报告问题

发现安全问题请不要公开开 issue，走仓库的 **Security → Report a vulnerability**（私有披露）。
